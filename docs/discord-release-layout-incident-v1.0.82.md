# Discord release layout incident — v1.0.82

## Incident

The v1.0.82 external-delivery workaround bypassed `scripts/release-notify.mjs` and constructed a reduced release notification directly inside a temporary workflow. The resulting Discord post omitted the canonical detailed Mission Brief, deployment-verification matrix, release links, integrity signature and canonical receipt path.

## Required permanent contract

Command Nexus release announcements must always use the canonical three-embed Release Control layout generated by `scripts/release-notify.mjs`:

1. Cyan production release status.
2. Purple Mission Brief generated from the complete versioned changelog section.
3. Green Deployment verified panel with GitHub, Greasy Fork, integrity, release links, SHA-256 and immutable commit footer.

No workflow may construct an alternative release embed directly. Greasy Fork delays must delay the canonical notification rather than trigger a reduced interim release card or second announcement.

## Current repair

The malformed v1.0.82 message is removed using its recorded webhook receipt. The immutable v1.0.82 tag is then revalidated against Greasy Fork and passed through the canonical notifier, leaving exactly one canonical Discord receipt.
