# Nexus 3.0.43.46 — local requirement selection test

Recognised missing-vehicle chips are manual selection buttons. Clicking one selects only the remaining suitable loaded vehicles using the existing matching rules and arrival order. Already selected and incoming vehicle IDs count once; on-scene units are excluded because the native missing count has already accounted for them. Saved exact-type rules take precedence over the display catalogue. Capacity-based towing requirements retain car-space counting.

Buttons never dispatch or request more vehicle pages. A blue tick shows coverage; an orange `! N short` and a status message identify a remaining shortage. Loading more vehicles through the game and clicking again retries the shortage. Clicking an already-covered requirement does not add more units. Native click rejection is respected. Unknown selected/incoming vehicle types stop selection instead of being treated as zero coverage. Unsupported personnel, water-volume and unrecognised requirements remain text.

The Settings switch **Mission window → Click missing vehicles to select units** is independent of the blue-tick switch. Both use the existing per-document preferences; reload the mission after a settings change. Keyboard activation works without submitting the mission form.

The only executable runtime addition is the manual bridge in `runtime/manual-requirement-selection.inc.js`, embedded verbatim in `runtime/nexus-runtime.js`. A hash regression reconstructs and verifies the exact tested .45 runtime after removing this bridge and reverting version markers. Existing Auto, dispatch, pagination, logger and recovery routines are unchanged. Manual clicks are blocked in hidden/background worker frames, during local Auto selection, and while rules are loading. Work is bounded to 100 candidate attempts per click and yields between native selections. It cancels when the document is suspended or the mission/requirements change. No new background timer is added.

Validation is recorded in `audit/verification-summary.json`: the full verification command is `node scripts/verify-all.mjs`. The new browser test uses the actual packaged extension with an isolated Edge profile and mocked network; it covers repeat clicks, arrival order, OR alternatives, deduplication, unavailable vehicles, load-more retries, capacities, saved rules, keyboard input, settings and worker exclusion. The UI preview is `audit/requirement-buttons-46.png`. Live gameplay and long-running RAM behavior require the user's local test and are not claimed by the fixtures.

Local delivery is generated by `native-navigation/build-requirement-buttons-46.mjs` from the workspace root after all eleven verification stages pass. It verifies the canonical ZIP and extracted files and preserves the public .45 reporting destination without reading credentials. Delivery is `manual-install/Nexus-Extension-3.0.43.46-LOCAL-REQUIREMENT-BUTTONS.zip` plus the extracted folder.
