# Nexus 3.0.43.50 — local station tabs and next course

Adds station-type filter tabs to the native course personnel-selection screen. **All**, **Stations**, **Home response**, and the individual types present are available. Standard/small Fire, Police and Ambulance stations share their respective type tab. Stations includes known non-home building types; missing or invalid metadata stays under **Type unavailable**, and future numeric types receive an explicit ID label. Classification uses `/api/buildings` `building_type` joined by building ID, not station captions. UK Home Response Location is type 22, checked against the local LSS `en_GB/buildings.ts` reference.

Type filtering combines with dispatch centre and station-name search. Each tab count reflects those other two filters. Already-selected personnel stay visible and selected even when their station does not match the type. Clear filters resets all three controls. Metadata refresh and later native station rows update the tabs, while an empty selected type stays selected rather than showing unrelated stations. Tabs wrap for phones and support keyboard navigation and pressed-state accessibility. This uses the existing single building metadata read; tab changes do not fetch personnel, vehicles or buildings.

**Educate + select again now opens a DIFFERENT advertised session of the SAME course**, superseding .49's same-session return. It submits through native Educate once. After the game confirms enrolment, it reads the open-course table, matches the current course's name and type, excludes the submitted course ID and prefers the next matching session with exactly **10 free places**. If none has exactly 10, it prefers a larger available session, then the next matching session with any free places. Native list order is used, starting after the current session if it is still in Open Courses, wrapping when necessary. Closed, unknown-capacity, own-only and unrelated courses are excluded. It never enrols the next batch automatically.

The fresh course opens with no selected staff and restores dispatch-centre, station-name and station-type filters. If the current course is absent from the list, its heading is matched only when the name identifies one unambiguous course type. No eligible course, ambiguous matching, failed reads or unconfirmed enrolment leave the result visible with a View courses link. There is no POST retry. One bounded course-list GET is made only after this explicit action succeeds; an already displayed native course list can be read in place. Lookup is cancelled when leaving the page.

Settings > Schooling retains **Course personnel filters** for all personnel filters and **Educate and open the next course** for the action. Existing course dropdowns, crew shortcut and manual requirement buttons remain included. Runtime changes are build markers only. Base: local .49 `e45c00a3`. **Local only. Do not push, merge, tag or publish without a subsequent explicit request.**
