# Live evidence and screenshot plan

Use the currently approved build and a controlled game account. Obtain the exact access procedure from the maintainer first. Record build, browser, date and action outcome for each capture. Remove personal names, player/alliance identifiers, tokens, private URLs and unrelated desktop content. Add highlights to the actual controls. Do not replace screenshots with generated UI.

| Tutorial | Required captures |
|---|---|
| Installation | Official listing/version; enabled extension; supported game popup |
| Account | Discord sign-in control; returned signed-in state; device/cloud settings choice |
| Interface | Help-menu entry; Tools tabs; mission controller |
| Naming | Dispatch/station scope; preview; verified saved captions |
| Personnel | Scoped register controls; completion report; preview and verified assignment |
| Profiles | Editor and saved profile; matching station selector; removal/purchase review; verified result |
| Dispatch | Exact requirement; saved custom mapping; selected/en-route units and readiness |
| Auto Mode | Start/stop controls; stages; successful cycle; low-queue wait; transport handoff |
| Alliance | Filters; small batch status; stopped state |
| Advanced | Realism/staging setup; schooling filters/action; credit summary/history; transport controls |
| Troubleshooting | Exact stopped status and sanitised diagnostic-export control |

Saving a profile is safe preparation. Do not perform a destructive application merely to obtain a screenshot. A real removal/purchase needs the user's explicit intent for the actual listed operation. For manual examples, stop automation and check intended missions and units before dispatch.

When captures exist, replace Screenshot pending paragraphs with Markdown images and descriptive alt text. Include expected results for all live actions and update publication checks. Fixture captures, if used, must stay explicitly labelled synthetic and do not satisfy live verification.
