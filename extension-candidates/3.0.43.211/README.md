# Nexus 3.0.43.211 choose-first upgrade selection

Stacked on .210. Existing pricing budgets, fresh result verification, personnel
sync, personal Auto Mode and optional Alliance Auto are preserved.

Load upgrade list retrieves the inventory. Filter it, then Load upgrade choices
reads one native station example per filtered building type, without expansion
price requests or purchases. This avoids a full scan just to choose requested
extensions or specialisations and includes owned/blocked options as intentions.
The game still supplies every actual per-station action and credit price.

Scan and select needed checks a manually chosen subset, or all filtered matches.
It selects eligible outstanding work, excludes built/construction/prerequisite
cases with row reasons, and keeps failed reads visible and purchase-blocking.
Partial matches keep only eligible work. Changing bulk choices requires rescan
and reconsiders the original scope; checkbox edits reset to a manual subset.
Review rechecks selected stations. Maximum credits and .210 purchase checks
remain mandatory. No scan issues a purchase or retries an uncertain purchase.

43 intercepted Edge upgrade checks include ten new workflow cases: choices
before selection, one sample read, ownership without native purchase IDs,
original-scope rescan, partial matches, blocked prerequisites, dispatch-centre
and manual-subset scope, failed-read retry, maximum level and mobile layout.
Audit, update notice, priority, memory, claims, Alliance Auto and checkpoint
regressions run separately. No real game purchases or store submission.
